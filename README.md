# ちょい便 — Choibin

近くのPCやスマホへ、ちょいと渡す。

同じ Wi-Fi / LAN につながっている **PC 同士**、そして **スマホ ↔ PC** の間でファイルを直接やりとりするアプリです。
クラウドもアカウントも使わず、データはネットワークの外に出ません。転送はすべて暗号化されます。

---

## 最初に知っておいてほしいこと

Apple の AirDrop 本体には Windows から参加できません。AirDrop は Apple 独自の AWDL という
無線プロトコルを使っていて、公開仕様がなく、対応するのは Apple 製の Wi-Fi チップだけです。
市販の「Windows で AirDrop」を名乗るソフトも、実際には AirDrop に接続しているのではなく、
同じ LAN 上での独自転送を行っています。

「ちょい便」も同じ方針で、**同じ使い心地を別の仕組みで実現**します。

| やりたいこと | 「ちょい便」での方法 |
|---|---|
| Windows → Windows | アプリ同士が自動で見つけ合い、選んで送る |
| iPhone / Android → Windows | PC の QR コードを読む → ブラウザーでファイルを選ぶ（アプリ不要） |
| Windows → iPhone / Android | PC でファイルを「公開」→ スマホのブラウザーから保存 |
| Mac の AirDrop に直接送る | できません（Apple の仕様が非公開のため） |

## ビルドと実行

必要なもの: **Visual Studio 2022**（「.NET デスクトップ開発」ワークロード）と **.NET 8 SDK**

1. `Choibin.sln` を Visual Studio で開く
2. F5 で実行（または Ctrl+Shift+B でビルド）

コマンドラインなら:

```
dotnet build Choibin.sln -c Release
dotnet run --project src/Choibin/Choibin.csproj
```

### 初回起動時のファイアウォール

最初に起動すると Windows Defender ファイアウォールの確認が出ます。
**「プライベート ネットワーク」にチェックを入れて許可**してください。
これを拒否すると相手から見つけてもらえません。

あとから許可する場合は、同梱の `ファイアウォール許可.bat` を右クリック →
「管理者として実行」してください。

## 使い方

### PC 同士で送る

1. 送る側と受け取る側の両方で「ちょい便」を起動する
2. 数秒で左の「近くのデバイス」にお互いが出てくる
3. 送る側でファイルをドロップし、相手を選んで「選んだデバイスへ送る」
4. 受け取る側に確認ダイアログが出るので「はい」

「確認せずに自動で受け取る」にチェックを入れると、ダイアログなしで保存されます。

### スマホから PC へ送る

1. PC の右側に出ている QR コードを、スマホのカメラで読む
2. 開いたページで「ファイルを選ぶ」
3. 選んだ瞬間に転送が始まり、PC の受信フォルダに保存される

iPhone でもアプリのインストールは不要です。Safari だけで動きます。

### PC からスマホへ送る

1. PC でファイルをドロップして「スマホに公開」を押す
2. スマホのページ下部にファイルが並ぶので、タップして保存

## 暗号化

### PC 間（常に有効・切れません）

接続するたびに、その場かぎりの鍵を作って交換します。

| 段階 | 使う技術 |
|---|---|
| 鍵交換 | ECDH（楕円曲線 P-256）— 公開鍵だけを交換し、鍵そのものは線に流れません |
| 鍵導出 | HKDF-SHA256 — 方向ごとに別々の鍵と IV を作ります |
| 本体 | AES-256-GCM — 64 KiB ごとのレコードに分けて暗号化します |

鍵は接続のたびに捨てるので、通信を録音しておいて後から解読することはできません
（前方秘匿性）。レコードには連番を混ぜた nonce を使い、長さヘッダーも認証対象に
含めてあるため、**並べ替え・欠落・再送・改ざんはすべて復号エラーとして弾かれます**。

### 確認コード

鍵交換だけでは、間に入った第三者が両側と別々に鍵を交換する「中間者攻撃」を防げません。
そこで共有秘密から **6 桁の確認コード** を導出し、受信ダイアログに表示します。

送る側と受け取る側で同じ数字が出ていれば、間に誰もいません。
設定の「送信前に確認コードを見比べる」を入れると、送信側でも送る前に数字を確認できます。

### スマホとの通信

自己署名証明書による **HTTPS**（TLS 1.2 / 1.3）で待ち受けます。設定で切り替えられます。
LAN 内のプライベート IP に対しては認証局が証明書を発行してくれないため、証明書は
アプリが自分で作ります。そのためスマホのブラウザーは初回に警告を出します。
「詳細」→「アクセスする」で進んでください。通信自体はきちんと暗号化されます。

証明書は `%AppData%\Choibin` に保存し、PC の IP アドレスが変わったときだけ作り直します。

さらに、起動のたびに **8 文字のアクセスキー** を作ります。QR コードに埋め込んであるので
読み取った端末はそのまま入れますが、同じ LAN の別の人が URL を打っても弾かれます。
アプリを再起動するとキーは変わります。

## 使うポート

| 用途 | ポート | プロトコル |
|---|---|---|
| デバイス検出 | 53317 | UDP（ブロードキャスト / マルチキャスト 239.77.77.77） |
| PC 間のファイル転送 | 53318 | TCP |
| スマホ向けページ | 53319 | TCP（HTTP） |

ポートを変えたい場合は `src/Choibin/Core/AppSettings.cs` の定数を書き換えてください。

## 画面まわり

配色は AirDrop / macOS に寄せています。アクセントは iOS のシステムブルー相当（`#0A84FF`）、
背景は Finder のウィンドウに近い薄いグレー（`#F4F6F9`）です。

近くのデバイスは AirDrop と同じく **丸いアイコンをグリッドに並べる** 形にしました。
背面には電波が広がる同心円を置き、相手を探している間だけ外側の円がゆっくり脈打ちます。
スマホ向けページも同じ配色に揃えてあります。

なお、これは Apple の AirDrop の外観をそのまま複製したものではなく、
同じ系統の視覚言語（青、丸いデバイスアイコン、同心円）を使った独自の画面です。

```
   ├ app.ico                         アプリアイコン（16〜256px を収録）
   ├ App.xaml / App.xaml.cs          配色とスタイルの定義
   ├ MainWindow.xaml / .cs           画面と全体の制御
   ├ Core/
   │  ├ AppSettings.cs               設定の保存と既定値
   │  ├ NetUtil.cs                   IP 取得・容量表示・ファイル名の安全化
   │  ├ SecureChannel.cs             ECDH 鍵交換と AES-256-GCM 暗号ストリーム
   │  ├ PhoneCertificate.cs          HTTPS 用の自己署名証明書
   │  └ QrEncoder.cs                 QR コード生成（外部ライブラリなし）
   ├ Models/Models.cs                デバイスと転送の状態
   ├ Net/
   │  ├ PeerDiscovery.cs             UDP でお互いを見つける
   │  ├ DropServer.cs                受信側の TCP サーバー
   │  ├ DropClient.cs                送信側の TCP クライアント
   │  └ WebServer.cs                 スマホ向けの簡易 HTTP サーバー
   └ Web/
      ├ phone.html                   スマホで開くページ
      └ touch-icon.png               ホーム画面に追加したときのアイコン
```

外部の NuGet パッケージは一つも使っていません。オフラインのままビルドできます。

## 技術メモ

**デバイス検出**
UDP 53317 にバインドし、4 秒ごとに自分の名前と転送ポートをブロードキャスト
（およびマルチキャスト）します。相手の通知を受け取ったら直接ユニキャストで返事を
返すため、起動直後でもすぐ一覧に並びます。16 秒間通知が来ないデバイスは一覧から消えます。

**PC 間の転送**
接続直後に鍵を交換し、以降はすべて暗号化されたレコードとして流れます。
その内側は `4 バイトのヘッダー長 → JSON ヘッダー → 1 バイトの承諾応答 → ファイル本体を連結`
という単純な手順です。ヘッダーには送信者名とファイル名・サイズの一覧が入ります。
暗号化の部分は `Core/SecureChannel.cs` に `Stream` の派生クラスとしてまとめてあるので、
転送側のコードは暗号化を意識していません。

**スマホ向けページ**
`HttpListener` ではなく `TcpListener` の上に最小限の HTTP を実装しています。
`HttpListener` で `localhost` 以外を待ち受けるには管理者権限か `netsh http add urlacl` が
必要になるためです。アップロードは `multipart/form-data` を使わず、
`POST /u?name=...` の本文にファイルをそのまま流し込む方式にしてあります。

**QR コード**
バイトモード / 誤り訂正レベル M / 型番 1〜6 に対応した実装を同梱しています
（`Core/QrEncoder.cs`）。LAN 内の URL を表示するには十分な容量（最大 106 バイト）です。

## 制限

- IPv4 のみ対応です
- 相手が本人かどうかは確認コードを目で見比べる方式です。鍵を覚えておく仕組み（TOFU）は入れていません
- スマホ向けの証明書は自己署名なので、ブラウザーの警告を一度受け入れる必要があります
- フォルダーをドロップした場合、直下のファイルだけを対象にします（再帰しません）
- ゲスト Wi-Fi など端末同士の通信が遮断されたネットワークでは相手を検出できません
